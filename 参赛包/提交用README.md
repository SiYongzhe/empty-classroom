# 空教室查询 —— 出门前 30 秒知道哪间教室空着

## 解决什么问题

北信科的同学想自习，但不知道哪间教室现在空着，只能一层层楼走上去找，运气不好要走三层。
现在打开网页，选时间和楼栋，30 秒内看到哪几间空、还能连空几节。

**在线体验：** <https://snazzy-sprite-379ec1.netlify.app>

## 主要功能

- **今天 / 明天 + 五个节次**：打开自动定位到当前时段（上课中→当前节，课间→下一节，已下课→明天第一节）
- **楼栋筛选 + 搜索**：WLA / WLB / WLC / XXB / XXD / GXB / 图书馆，也可直接搜「WLA-310」
- **空教室卡片**：楼层、座位数、设施标签，以及「接下来还能连空几节」
- **教室详情**：点卡片看这间今天/明天每一节是空还是有课
- **收藏**：常去的教室点 ☆，下次排最前
- **AI 推荐**：写一句「安静、有插座、能坐 4 个人」，从当前空教室里挑一间并说明理由

## 怎么运行

**在线：** 直接打开上面的链接，手机也能用。

**本地：**

```bash
python -m http.server 8000
# 打开 http://localhost:8000
```

## 用了什么技术

| 部分 | 用了什么 | 为什么选它 |
| --- | --- | --- |
| 页面 | HTML + CSS（原生） | 不用框架，改完刷新就能看，没有构建步骤 |
| 交互 | 原生 JavaScript | 代码量小，报错好查，队友能看懂 |
| 数据 | 静态数据 + 确定性伪随机 | 不需要后端和数据库 |
| AI | DeepSeek + Netlify Function 代理 | Key 放服务端，浏览器里没有 |

**架构一句话**：纯静态页面 + 一个 serverless 函数。函数只做一件事——替浏览器转发 AI 请求，
这样 API Key 存在服务器环境变量里，任何人 F12 都拿不到。

## AI 使用披露

**用 AI 做了什么：**
- 生成 CSS 布局初稿；解释 `localStorage` 与 `URLSearchParams` 的用法；协助排查报错
- 生成《新手参赛执行手册》《答辩与演示包》的文字初稿，之后人工删改

**自己写的部分：**
- 数据模型（楼栋/教室/节次结构）、排序规则（按连空节数而非座位数）
- 时间推断逻辑（上课中 / 课间 / 已下课三种状态）
- 全部前端交互、空状态与错误处理、部署与故障排查
- 全部文案与答辩讲稿

**AI 生成后我改了哪里：**
- AI 给的卡片布局在手机上挤成两列，改成 600px 以下单列
- AI 建议用随机假数据，改成确定性哈希——否则刷新一次空教室就全变，演示时当场穿帮

## 已知限制

- **教室编号取自真实课表**（WLA-310、XXB-605 这些），但**占用状态是模拟的**，没有接教务系统
- 只覆盖 7 栋楼 28 间教室，实际可用教室远不止这些
- 只支持今天/明天，没有日历
- 收藏只存在本机浏览器，换设备不同步
- 没有教室实时人数（需要门禁或传感器数据）
